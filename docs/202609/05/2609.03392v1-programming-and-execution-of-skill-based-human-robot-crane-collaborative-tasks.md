## 摘要
高度多变的生产批次给机器人制造和室内物流带来了日益严峻的挑战。需要新的敏捷性、灵活性和鲁棒性能力。机器人技能将运动、工具操作和传感器感知集成在一起，为参数变化的多类任务提供了一致性的执行机制。本文展示了一种基于CAD模型的易用编程与执行系统，用于参数化技能和技能监控。执行控制结构基于改进的行为树，是动态且参数化的，仅使用基于事件的通信。本文以一个测试示例展示了人-机器人-起重机协作技能，其中人类指挥桥式起重机和机械臂，将由起重机支撑并由机械臂引导的重物插入目标位置。

## Abstract
Highly varying production sets increasing challenges for robotic manufacturing and indoor logistics. New capabilities for agility, flexibility, and robustness are needed. Robot skills, integrating motions, tool operations, and sensor perceptions consistently provide an execution mechanism for a versatile set of tasks with varying parameters. In this paper, easy-to-use CAD-model based programming and execution system for parametrized skills and skill monitors is showcased. The execution control structure is dynamic and parametrized, based on a modified Behavior Tree, where only event based communication is used. A human-robot-crane collaborative skill is shown as a test example, where a human instructs an overhead crane and a manipulator in inserting a heavy object supported by the crane, and guided by the manipulator, into the goal.

- 传统机器人编程方式难以应对频繁变化的产品规格、产品组合和物料流干扰，**亟需一种易于编程、灵活复用且具备感知与容错能力的执行机制**。
- 论文认为**机器人技能（robot skills）**（将运动、工具操作与传感器感知有机集成）是应对上述挑战的关键执行单元；同时，工业环境中的**重型设备（如桥式起重机）与人类操作员**仍将长期参与制造流程，但现有系统大多无法将机器人、起重机与人类高效纳入同一任务框架。
- 论文提出一种**基于CAD模型的技能编程与执行系统**，以支持人-机器人-起重机的三方协作任务，旨在简化复杂多变场景下的任务配置与执行管理。

## 2. 论文提出的方法论：核心思想、关键技术细节与算法流程

### 核心思想

- 将复杂制造任务拆解为三层控制结构：**任务层（task layer）→ 技能层（skill layer）→ 原语层（primitive layer）**。
- 采用**改进的行为树（modified Behavior Tree, BT）** 作为任务控制结构，取代传统有限状态机，实现动态组合与并行执行。
- 通过**可参数化技能 + 可配置监控技能（monitor skills）** 构建执行系统，使任务既能适应参数变化，又能在异常发生时及时响应与恢复。

### 关键技术细节

1. **三层控制架构**
   - 任务层包含行为树控制节点与条件节点；
   - 技能层包含执行技能与技能监控节点（行为树叶节点）；
   - 原语层由原子操作（如规划轨迹、执行抓取、触发感知）组成，用于与物理世界交互；
   - 技能与原语之间通过**事件与消息机制**同步协作。

2. **事件驱动行为树（Event-driven BT）**
   - 与标准BT的**tick轮询机制**不同，该系统采用**纯事件驱动通信**——只有事件发生或数据更新时才触发节点响应，从而降低CPU资源消耗、提高响应实时性。
   - 对**并行节点（parallel node）** 进行了逻辑改造：开发者可**自定义失败阈值（K）与成功阈值（M）**。例如，多个监控器与一个主技能并行运行，任意监控器失败即时触发父节点失败反馈，从而显著增强系统的反应速度与容错能力。

3. **技能建模与状态控制**
   - 技能控制流使用**UML活动图建模**，并映射为**有限状态机实现**（如图4、图5所示）。
   - 技能执行器在独立进程中运行，通过通信接口与行为树父节点进行消息交互。

4. **CAD模型驱动的任务规划与参数化**
   - 基于**OpenCascade CAD内核**开发了任务规划软件，可直接在CAD模型上选取面、边、顶点等特征，用于定义技能参数（如抓取姿态、视觉伺服路径点、螺丝孔位置）。
   - 参数既可**从CAD模型自动生成**，也可由操作员手动设置（如受监控力的阈值等）。
   - 任务配方以**JSON格式**描述，可通过文件或TCP/IP传递给任务控制器。

5. **监控机制设计**
   - 监控技能（Monitor）与具体技能解耦，可在行为树中**灵活配置**——既可多个监控器协同监控单一技能，也可单个监控器同时监测多个并行技能；
   - 监控器从原语层获取数据，发现异常后向上层报告失败，触发**Fallback恢复分支**执行纠正操作。
   - 论文提供了三种监控器示例：TimerMonitor（超时监控）、ForceMonitor（力监控）、YankMonitor（力的导数突变监控，用于判定抓取是否成功）。

6. **世界模型（World Model）**
   - 运行时环境信息统一存储在世界模型中，技能执行过程中可通过查询获取目标姿态等状态；
   - 感知原语持续更新世界模型，完成对工件和目标的定位与跟踪。

## 3. 实验设计：使用了哪些场景、基准及对比方法

- **应用场景**：搭建了一个**人-机器人-起重机协作的装配任务**测试台。实验目标是：桥式起重机承托重物，机械臂（KUKA LBR iiwa 14）通过推力引导载荷，将重物对准目标对象并插入到位，随后由**人类操作员执行螺丝紧固**操作。
- **任务流程**：
  1. Localize（定位物体）
  2. Attach robot to load（吸附载荷，由Yank监控器并行判断是否抓取成功）
  3. Insert visually guided（视觉伺服引导插入，使用3D视觉伺服 + 导纳控制器协同控制机器人/起重机）
  4. Screw（请求人类操作员按提示完成拧螺丝并确认）
- **硬件平台**：
  - 机器人：KUKA LBR iiwa 14 R820 + Sunrise控制器
  - 起重机：Konecranes CXT Smart桥式起重机（PLC控制，载荷上限3200kg）；前期也使用KUKA Quantec KR 210模拟起重机
  - 夹具：Schmaltz磁力抓具
  - 视觉：Photoneo MotionCam 3D相机（与机器人基座进行手眼标定）
  - 通信：ROS2 Topics与Services

- **结论一**：提出了一种基于CAD模型和技能库的端到端编程与执行系统，能够在真实工业硬件上执行“人类-机器人-起重机”多方协作的任务，验证了方法的可落地性。

- **结论四**：通过行为树的事件驱动改造，实现了比传统tick式BT更高效的运行机制与更强的工况适应性。

## 7. 优点

### 方法上的亮点
- **无需ontology/描述性编程（PDDL）即可上手使用**：底层虽为软件框架，但使用了“GUI + CAD交互选特征 + 手工补充参数”的友好式配置流程，降低了学习门槛。
- **技能与监控解耦的设计**：监控器可复用于多个技能或多个并行技能组合，进一步增强了任务编排的灵活性。
- **行为树改造具有良好的实用性**：并行节点支持自定义成功/失败阈值，同时并行多个监控器、多个技能，实现“多技能并行执行+多监控器守护”的复杂流程编排。
- **事件驱动的通信机制**提高了资源效率和系统的反应实时性，在其早期相关研究基础上加入了面向工业部署的改进。

### 实验设计亮点
- 使用**真实商用起重机（最大荷载3.2吨）与真实工业机械臂、磁吸抓具**，并非仅停留在仿真层面；
- 以**人类操作员实际参与拧螺丝**完成闭环交互，验证了系统与人的融合能力；
- 阐述了详细的硬件-软件架构（服务与Topic结构），对其他研究团队具有一定**复现指导价值**。

## 8. 不足与局限

- **实验验证的深度不足**：仅有一个演示性装配案例，未能提供关于成功率、节拍时间、失败恢复时间等定量指标，实验的可说服力偏弱。
- **缺乏横向对比**：没有在相同任务上对比SkiROS2、FSM等替代架构的效率或开发难度，结论的可泛化性有待进一步证明。
- **泛化能力的边界未讨论**：虽声称可用于重物搬运，但实际使用的是3D打印模型的小型原理样件，对真实重载荷、结构变形、起重机非线性/大惯性等场景的适用性表述有限。
- **CAD规划与行为树之间**更偏重“人工配置 + 自动参数提取”，**并非全自动的任务规划器**，不支持完全自主推理/生成新任务流程。
- **可扩展性有待观察**：在遇到更复杂任务、更多并行技能与监控器交错时，事件驱动BT的调度冲突与异常恢复策略需要更深入的理论分析。
