## 摘要
从少量演示中学习的机器人通常需要两种泛化能力。组合泛化通过重新组合技能来解决新任务，而技能泛化则使每个技能背后的学习策略能在新情境中工作。两者相互依赖，但在组合与其所调用的技能之间会丢失信息。技能在何处有效由其策略训练时所依据的结构决定，而组合只能通过一个单独的、省略了该结构的描述（例如名称、指令或符号算子）来了解该技能。我们的核心思想是将每个策略的结构先验作为组合与技能之间接口的一部分。结构先验说明了某一行为依赖于什么，例如抓取仅依赖于夹爪相对于物体的位姿。将其嵌入训练时，它塑造了策略泛化的适用范围；用语言表述时，它告诉组合该策略适用于何处。我们在智能体先验引导的策略学习（Agent Priors-guided Policy Learning, APPL）中实现了这一思想。一个构建智能体将完整演示分割为可复用技能，为每个技能提出若干结构先验，并针对每个先验训练和验证一个策略。随后，一个运行时智能体在这些特定于先验的策略中进行选择，并利用它们的接口将其组合以达成新的任务目标。在 MetaWorld 和长时程 ManiSkill 任务上，APPL 提升了分布外技能泛化能力，并实现了此前未见的技能组合；消融接口信息会显著降低性能。这些结果支持将训练时的结构假设作为技能学习与技能组合之间的桥梁。

## Abstract
Robots that learn from a few demonstrations often require two forms of generalization. Compositional generalization recombines skills to solve new tasks, and skill generalization lets the learned policy behind each skill work in new situations. The two depend on each other, yet information is lost between composition and the skills it calls. Where a skill works is determined by the structure its policy is trained with, while composition sees the skill only through a separate description, such as a name, an instruction, or a symbolic operator, that omits this structure. Our key idea is to use each policy's structural prior as part of the interface between composition and the skill. A structural prior states what a behavior depends on, for example that a grasp depends only on the gripper's pose relative to the object. Built into training, it shapes where the policy generalizes; stated in language, it tells composition where the policy applies. We instantiate this idea in Agent Priors-guided Policy Learning (APPL). A construction agent segments complete demonstrations into reusable skills, proposes several structural priors for each skill, and trains and verifies one policy per prior. A runtime agent then selects among these prior-specific policies and composes them toward new task goals using their interfaces. Across MetaWorld and long-horizon ManiSkill tasks, APPL improves out-of-distribution skill generalization and enables previously unseen skill compositions; ablating the interface information substantially reduces performance. These results support the use of training-time structural assumptions as a bridge between skill learning and skill composition.

# 《Agent Priors-guided Policy Learning (APPL)》论文总结

## 1. 核心问题与整体含义

- **背景**：机器人部署时面临两类泛化：
  - **组合泛化**（compositional generalization）：把已学技能重新组合以完成新任务；
  - **技能泛化**（skill generalization）：每个技能的策略能在新情境（物体移位、被前序技能留下的状态）中继续执行。
- **核心矛盾**：二者相互依赖，但**信息在任务层与技能层之间丢失**。
  - 技能"在哪里有效"由其策略训练时所用的结构决定；
  - 组合层只能通过**名称、指令或符号算子**这类省略了结构的描述来调用技能。
- **后果**：组合层不知道技能的真实适用范围 → 要么在策略会失败的条件下调用（接口不忠实），要么放弃可用调用（接口信息量不足）。
- **论文主张**：把每个策略的**结构先验（structural prior）**本身作为组合层与技能层之间的接口。
  - 先验嵌入训练 → 塑造策略泛化的**覆盖范围（coverage）**；
  - 同一先验用自然语言表述 → 告诉运行时智能体该策略**适用于何处（selection）**。
- **接口的两个理想性质**：忠实性 $A_i \subseteq W(\pi_i)$、信息量 $A_i \approx W(\pi_i)$，其中 $W(\pi_i)$ 是策略的真实成功区域，$A_i$ 是接口声明的适用区域。

## 2. 方法论：APPL

### 2.1 核心思想
- 用同一个结构假设承担**双重角色**：训练实现（决定 $W(\pi_i)$）+ 运行时描述（构成 $A_i$）。
- 不同技能、不同情境适用的结构不同，因此**为每个技能保留多个先验对应的多个策略**，而不是固定一种抽象。

### 2.2 离线构建阶段（构建智能体，只做一次）
1. **技能分割**：把 $N$ 条完整、未分割的示范切分为可复用技能数据集 $D_k$，按物理职责划分边界，**相邻技能在交接处刻意重叠**（后继技能的监督数据包含前驱结尾与后继开头），从而扩大后继策略的启动集，且不引入额外示范数据。
2. **先验提出**：每个技能提出约 3 个**互补**先验（期望失败模式不同），至少一个针对被操作/接近物体的位移（如物体相对坐标系）；再依据验证反馈追加 1 个（h04）。
3. **训练实现**：每个先验对应一个独立的 Diffusion Policy（共享 U-Net 骨干、共同训练配方），差别体现在**输入表示、动作参数化/参考系、编码器、辅助损失**：
   $$\theta_i = \arg\min_{\theta \in \Theta_{\rho_i}} \mathbb{E}_{D_{k(i)}}[\ell_{BC}(\theta)] + \lambda_i \ell^{aux}_{\rho_i}(\theta)$$
   物体相对坐标的动作变换示例：$x^{loc}=R_t^\top(x^{world}-p_t)$，$\Delta x^{world}=R_t \Delta x^{loc}$；解码出的末端目标由共享 IK 模块转为关节指令。
4. **验证**：仅用**示范中的技能入口状态**，每条策略执行 1.5 倍段长，按固定退出条件评分；构建智能体据此写报告并设计 h04。
5. **接口文档**：$I_i = (d_i, h_i, s_i, v_i)$，即**先验描述、交接条件、训练支撑（support）、验证证据**，并声明调用所需的类型化参数。适用区域假设为 $A_i=\{o:\phi_{\rho_i}(o)\in R_i\}$。

### 2.3 在线运行时阶段（运行时智能体）
- 策略库、接口、智能体模型/提示/工具全部**冻结**，不做权重更新，记忆每个 episode 重置。
- 每个决策点接收：任务目标 $g$、当前状态与目标谓词、近期交互历史、episode 笔记本、所有策略接口。
- 输出：策略选择 $i_j$、类型化参数与时长 $u_j$、停止条件 $m_{j+1}$，即
  $(i_j,u_j,m_{j+1}) \sim R_\alpha(\cdot \mid h_{t_j}, g, m_j, L)$，$a_{t:t+H}\sim \pi_{i_j}(\cdot \mid h_t, u_j)$。
- **执行器**逐步检查停止条件（可为绝对值或相对调用起点的相对值），满足即返回控制权；任务目标满足则立即中断。智能体可继续当前技能、切换到同技能的另一策略、换技能或结束任务。

### 2.4 形式化目标
- 构造即求解 $\max_{\sigma,\{\rho_i\}} J(S(\sigma,\{\rho_i\},D_N))$，其中 $J(S)=\mathbb{E}_{g\sim P_{test}, o^0\sim\mu_{test}(g)}[\mathrm{Succ}(g,o_T)]$。
- 由于该优化空间开放且部署目标在构建时不可得，故交由语言模型智能体来提出、实现与评估候选设计。

## 3. 实验设计

### 3.1 Exp. 1：技能泛化（只测覆盖，不涉及组合）
- **场景**：6 个改造版 MetaWorld 任务（pick-place-wall、assembly、drawer-open、door-open、peg-insert-side、stick-push），每任务 20 条脚本专家示范。
- **数据量**：$N \in \{2,5,10,20\}$ 嵌套示范集。
- **状态划分**：IID（示范区间内新采样）、C（重组两个空间因子）、E（两因子均外推），OOD = C 与 E 等权平均；每模型测 20 IID / 40 C / 40 E 状态，另有 50 个开发状态。
- **对比方法**：
  - **B0**：原版 Diffusion Policy；
  - **B1**：固定关系先验（三个预定义角色相对向量 + 小 MLP 编码）。
  - **候选 A1–A4**：由 GPT-6 Astra（reasoning effort max）设计并实现，共享骨干、2 万次更新预算、控制器与评测；q1 = 首个提案，q3/q4 = 按开发集 OOD 成功率选出的候选。
- **指标**：六任务宏平均 OOD 成功率 + 95% 配对分层 bootstrap 区间（2 万次重采样）。

### 3.2 Exp. 2：长时程组合（覆盖 + 选择一起测）
- **场景**：5 个 ManiSkill 长时程任务（drawer exchange、buffer exchange、retrieve and store、covered peg assembly、pour and return），每任务 12 条脚本规划器示范（无失败/恢复轨迹）。
- **对比方法**：
  - **DP**：单个全任务扩散策略；
  - **SinglePrior**：同一语言模型设计的单个全任务先验，无运行时智能体；
  - **Agent+VLA**：微调 π0.5（`lerobot/pi05_base`）替代整个库，运行时智能体用技能名作指令调用；
  - **四个消融**：w/o interface information（隐藏 $I_i$ 全部字段）、w/o prior information（保留验证分数与退出准则）、w/o HL agent（固定规则按示范顺序轮换策略）、w/o verification（每技能 3 个策略、无验证）。
- **三套评测**（每 case 一个 episode，共 5000 步上限）：
  - **Motion-level OOD**：每任务 8 个冻结布局，物体偏移 13–27.5 mm（超出示范 ±8–15 mm 范围）；
  - **Task-level OOD**：每任务 8 例（4 例从中途近似阶段续做 + 4 例只请求示范序列前缀）；
  - **Composition**：16 例跳过/重排技能，或在示范中不存在的入口条件下起始。
- **成功判定**：首次达成目标即计成功，执行器辅助停止。
