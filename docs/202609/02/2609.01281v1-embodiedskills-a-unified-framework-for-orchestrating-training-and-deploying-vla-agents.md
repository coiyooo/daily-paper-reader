## 摘要
视觉-语言-动作（VLA）模型将视觉观察和语言指令直接映射到机器人动作，但长期任务需要的不仅仅是动作预测。智能体必须在物理状态演变过程中协调感知、规划、执行、进度验证和恢复。动作预测或模型生成的技能决策本身并不能保证所提议的操作在当前状态下有效，也不能保证其结果将得到验证。我们提出EmbodiedSkills，一个统一框架，将每个技能决策视为执行提案：运行时在执行前检查其前置条件，并在之后验证结果。一个共享的可执行技能接口在单个智能体循环中连接高层技能选择、有界低层VLA执行和动作后验证。由于该接口保持固定，低层VLA策略可以在不更改智能体循环的情况下被替换或调整。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，为各个组件提供监督，并在可用交互反馈时支持可选的在线适应。我们在RoboTwin 2.0和LIBERO上使用Qwen3-VL和OpenPI/pi0.5实例化EmbodiedSkills。任务自适应的低层VLA策略在50个RoboTwin 2.0任务中平均成功率为86.20%，在四个LIBERO套件中为97.40%。这些结果确立了EmbodiedSkills中使用的任务自适应低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，相同的任务自适应执行方法实现了12.5%的平均成功率。该框架提供了一种可训练和可检查的智能体层，用于将这些策略转变为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体架构

EmbodiedSkills 提出一个统一的**具身技能（executable embodied skills）**框架，将技能决策视为"执行提案"：**运行时（runtime）在执行前检查前置条件，执行后验证结果**。它不替代现有 VLA 策略，而是在其周围建立结构化的智能体层。

### 2.2 核心设计：共享技能接口

每个技能定义为一个契约（contract）：

> k = (Xk, Yk, pre_k, exec_k, post_k, fail_k)

- **Xk / Yk**：类型化的输入/输出模式
- **pre_k**：前置条件
- **exec_k**：可执行操作
- **post_k**：执行后的状态更新
- **fail_k**：失败时的显式状态与证据映射

该契约同时充当**组合接口、运行时有效性边界、结构化训练轨迹来源**三重角色。

### 2.3 六阶段受控循环（AgentLoop）

循环状态机包含六个语义阶段：

1. **Observe（观察）**：采集视觉证据并更新场景表征
2. **Plan（规划）**：将任务分解为可验证的子目标，分配执行预算
3. **Preflight（预检）**：在物理动作执行前检查子目标就绪状态
4. **Execute（执行）**：通过低层 VLA 策略生成并执行一个**有界动作块（bounded action chunk）**
5. **Verify（验证）**：基于执行后的新证据判断子目标是否取得进展
6. **Recover（恢复）**：根据失败证据修订子目标或计划后重新进入循环

该循环**不是固定单向流水线**，而是根据当前任务状态动态路由：可重新观察、修订计划、继续执行当前子目标、推进到下一子目标，或进入恢复流程。

### 2.4 关键决策与守卫机制

- 高层策略有三种控制类型：
  - **RunSkill(k, q)**：执行某个技能
  - **AdvanceStage**：推进到下一阶段
  - **FinishRun**：终止循环
- **策略-运行时分离**：策略只负责提出决策，运行时通过守卫函数（guard）强制验证：
  - **技能守卫 Gskill**：检查阶段是否匹配、技能是否在该阶段允许、所有前置条件是否满足；
  - **推进守卫 Gadvance**：检查当前阶段是否产生后继所需证据；
  - **终止守卫 Gfinish**：允许终止。
- **非法/无效决策**不会被静默转为物理动作，而是**记录为被阻止的决策（blocked decision）**，保留证据供后续决策使用。

### 2.5 动作执行与验证

- 低层 VLA 策略输入：活动子目标、当前观察、机器人状态、预检证据；
- 输出：带执行报告的有界动作块；
- 动作块须通过数值合法性、动作类型、时间范围（0 < H ≤ Hmax）以及与当前子目标/观察一致性等检查；
- 执行后需获取**新鲜证据**再做下一决策，语义子目标可跨多个动作块完成；
- **验证**只评估当前活动子目标的完成度，输出语义路由 V = {Advance, Continue, Reobserve, Replan, Recover, Finish}，任务级最终成功率仍由环境评估器判定。

### 2.6 训练方法

- **组件级监督适应**为主要训练机制：
  - 规划器学习从指令+视觉上下文到有序语义子目标的映射；
  - 低层 VLA 策略通过子任务级示范进行微调；
  - 调度器（scheduler）在保持 VLA 冻结的条件下，学习部署一致的高层技能决策。
- **部署一致的训练样本**：训练输入边界与部署时完全一致——只包含该组件实际可见的上下文，不喂入部署时不存在的信息。
- **可选在线闭环节适应**：使用群体相对策略优化（GRPO 类方法），但仅作为可选的补充细化手段，不作为主要实验结果来源。

## 6. 主要结论与发现

1. **执行层性能**：任务自适应的低层 VLA 策略在 RoboTwin 2.0 50 任务上达到 **86.20%** 平均成功率（较 π0.5 参考值 82.74% 提升 **3.46 个百分点**）；在 LIBERO 上达到 **97.40%**（较 OpenPI 官方 96.85% 提升 **0.55 个百分点**）；RMBench 记忆依赖任务为 **12.5%**。
2. **子目标条件化是关键**：移除子目标条件化后成功率从 86.2% 骤降至 34.4%；仅保留一个动作块则跌至 19.5%，说明语义分解本身并不足够。
3. **中间验证不可或缺**：移除验证后成功率从 86.2% 降至 48.2%，固定的开环预算无法适应不同初始状态的实际执行过程。
4. **自适应延续有效**：同一语义子目标常需多个有界动作块，循环需要根据实际进度决定继续、推进或恢复。
5. **领域差距**：记忆依赖型任务（RMBench 12.5%）仍远低于长时程非记忆任务，说明当前 VLA 动作条件化方法在"动作由交互历史决定"的场景中面临显著挑战。

## 7. 方法贡献与亮点

- **策略-运行时分离是核心设计亮点**：由运行时强制前置条件、内容新鲜度、动作合法性和合法状态转移，将"模型提议"与"物理执行"显式分离，避免了 prompt 层面的隐式侥幸。
- **统一的技能契约设计精妙**：一个接口同时服务于组合、验证边界和训练轨迹收集，使高层规划器、验证器、低层 VLA 策略均可独立替换/适配而无需改动整个 AgentLoop。
- **失效传播控制**：通过工件（artifact）的新鲜度追踪，只使依赖被改变证据的工件失效，避免陈旧预测授权新物理动作。
- **部署一致的训练数据构造**：训练时不给组件提供部署时不可见的信息，减小了训练-推理分布不匹配。
- **消融实验设计干净**：三组消融各自独立地验证了"子目标条件化、中间验证、自适应多动作块"三个设计要素的因果贡献。
- **跨基准验证**：同一执行接口在双基准（RoboTwin 2.0 与 LIBERO）上都取得了竞争力的执行性能，说明接口具备一定通用性。

## 8. 不足与局限

- **上层组件质量依赖**：显式契约能阻止非法状态转移，但不能保证语义上貌似合理的决策一定正确——错误的物体定位或子目标可以满足模式校验却导致失败。
- **验证能力有边界**：任务进度被遮挡、视觉模糊或只能靠无法从可获取视角推断的属性时，验证器不可靠。
- **任务专用策略的开销**：50 个任务各需独立微调策略，训练、存储、部署成本高于单一通用策略。
- **延迟代价**：相比单次前向动作策略，额外 VLM 调用和动作后观察引入了显著延迟。
- **RMBench 记忆依赖任务上表现不足（12.5%）**，说明子目标条件化不足以处理需依赖交互历史判定正确动作的场景。
- **协调与长轨迹问题**：模块化引入协调开销，长 episode 中小的规划/执行误差会累积，导致更多的观察、重试和模型调用。
- **计算资源透明度不足**：未披露训练所需的具体 GPU 资源和时间。
- **仿真与真实的差距**：全部实验在仿真中完成；框架在真实机器人上的适用性有待验证。
