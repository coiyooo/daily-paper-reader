## 摘要
代理式人工智能框架解释开放式任务目标并将其分解为多步计划。关于具身特定能力、物理前提条件和跨机器人协调的更丰富信息能提升接地性，但仍不能消除不可行、时机不当或不安全的物理动作。因此，物理机器人团队需要在语义规划与执行之间建立一个明确的架构接口，在驱动前，每个计划动作都要针对机器人能力、系统状态和工作流约束进行验证。本文提出物理代理式人工智能（Physical Agentic AI），一种基于技能的机器人代理编排框架，其中每个机器人暴露一个可执行技能的带类型库，同时基础模型规划器将任务分解为多个阶段，并将每个阶段分配给一个机器人-技能对。机器人编排层将技能库、机器人状态、命名位置和工作流契约暴露给非执行的任务规划器，而确定性机器人编排器一次验证并授权一个技能。我们在无人机-UGV搜索与调度任务上进行了评估，每种条件下的每次任务都在Gazebo中实时执行；同时在人形-四足运输任务上使用硬件等效技能接口以及Unitree G1和Go2上的两次物理试验。通过独立改变规划器知识和运行时强制，我们发现检索将技能接地率从51%提高到96%，但仍使信息充分的规划器分派了23-29%的故障步骤。逐次分派强制将错误分派降低到0%，且没有错误阻塞；保持计划不变的消融实验证实了是闸门而非计划变化起作用。实时执行使这种差异在物理层面显现：没有强制时，所有八个注入的故障都越过了编排边界，其中六个产生了机器人运动；有强制时，八个都在运动之前被拒绝。

## Abstract
Agentic AI frameworks interpret open-ended task goals and decompose them into multi-step plans. Richer information about embodiment-specific capabilities, physical preconditions, and cross-robot coordination improves grounding, but does not eliminate infeasible, mistimed, or unsafe physical actions. Physical robot crews therefore require an explicit architectural interface between semantic planning and execution, where every planned action is verified against robot capabilities, system state, and workflow constraints before actuation. This paper introduces Physical Agentic AI, a framework for skill-grounded robot agent orchestration, in which each robot exposes a typed library of executable skills while a foundation model planner decomposes a task into phases and assigns each phase to a robot-skill pair. A Robot Orchestration layer exposes the skill library, robot state, named locations, and workflow contracts to a non-actuating Mission Planner, while a deterministic Robot Orchestrator validates and authorizes one skill at a time. We evaluate on a drone-UGV search-and-dispatch mission, where every mission in every condition is executed live in Gazebo, and on a humanoid-quadruped transportation task using hardware-equivalent skill interfaces plus two physical trials on a Unitree G1 and Go2. Varying planner knowledge and runtime enforcement independently, we find that retrieval raises skill grounding from 51% to 96% yet leaves informed planners dispatching 23-29% of faulted steps. Per-dispatch enforcement reduces false dispatch to 0% with no false blocks, and a held-plan ablation confirms that the gate, not plan variation, is responsible. Live execution makes the difference physical: without enforcement all eight injected faults crossed the orchestration boundary and six produced robot motion; with enforcement all eight were refused before motion.

- **研究动机**：大型语言模型（LLM）被广泛用于将自然语言任务映射为机器人行为，但 LLM 规划器生成的计划往往包含**不可行、时机不当或不安全的物理动作**。软件 Agentic AI 的编排假设（工具调用可重试、可回滚）在物理机器人团队中不成立，因为物理动作具有状态依赖性、耗时性和不可逆性。
- **核心问题**：现有系统把“规划器知道什么”（知识/检索）与“运行时实际允许什么”（强制/执行权）混为一谈。论文提出一个核心假设：**仅靠把更丰富的技能、前置条件、工作流约束注入 LLM 提示词，并不能保证物理安全的执行**；真正需要的是在语义规划与物理执行之间建立显式的架构接口，由确定性运行时对每个动作在驱动前进行验证与授权。
- **整体含义**：物理代理式人工智能（Physical Agentic AI）是一种系统架构范式，强调**基础模型只能提议，不能直接驱动**；唯一拥有执行权的是确定性机器人编排器。这一分离是异构机器人团队安全自主执行的关键设计原则。

## 2. 论文提出的方法论

- **核心思想**：将 Agentic AI 的任务分解能力与经典机器人学中的状态检查/前置条件验证相结合，通过“技能库→规划器→编排器”的管线，把语义推理与物理执行彻底分离。
- **架构四组件**：
  - **机器人技能库（Robot Skill Libraries）**：每个机器人暴露一个带类型的可执行技能库 \(K_r\)，每个技能定义参数、前置条件、预期效果、成本与同步要求。例如人形机器人暴露 `pick_place(object, location)`，四足机器人暴露 `navigate(location)`。
  - **任务规划器（Mission Planner）**：一个**非驱动（non-actuating）** 的 LLM 代理，负责理解用户请求、分解任务阶段、选择机器人–技能对，并生成结构化计划：
    \[
    \pi = \{(\phi_1, r_1, \kappa_1), \dots, (\phi_T, r_T, \kappa_T)\}
    \]
    计划合法要求每一步引用真实技能、参数合法、机器人可用、次序符合工作流。
  - **工作流契约（Workflow Contracts）**：声明式规范，编码跨机器人同步点、时序依赖、资源约束、参数合法性规则和**运行时绑定值**（state-bound values）。契约同时编译为规划器提示词和运行时检查器的规则，防止“模型看到的规则”与“系统执行的规则”漂移。
  - **机器人编排器（Robot Orchestrator, RO）**：确定性过程化运行时，而非模型。拥有**唯一执行权**，在每次技能驱动前执行五项检查：
    1. 技能是否存在于所选机器人；
    2. 参数是否合法且满足**请求包含性（request containment）**（不允许把用户指定的实体偷偷替换为别的可用值）；
    3. 当前步骤是否为工作流契约授权的下一个转换；
    4. 机器人当前状态是否满足技能/契约前置条件；
    5. 运行时绑定值是否已可用且有效（如“受害者的位置”需由另一机器人在执行时发布）。
- **执行协议**：检索上下文 → 规划器生成计划 → RO 全局校验（允许一次反馈重规划）→ 逐技能授权执行 → 契约违规在驱动前被拒绝，已执行步骤失败则停机报告。
- **关键技术机制**：
  - **动态目标绑定（Dynamic Goal Binding）**：规划器用符号占位符（如 `navigate_to(target="victim")`），RO 在驱动时从状态接口解析真实值；若值缺失或为 NaN 则拒绝（`no_target_fix`）。
  - **检索与强制的解耦**：检索（retrieval）获得知识，强制（enforcement）决定是否授权，两者独立变化。

    - **LLM-only**：无任何技能库；
    - **Skill-list**：仅提供技能注册表和作业区；
    - **RO-prompt**：提供技能+工作流约束，但**不强制**；

- **测试平台二：人形–四足物理团队（Unitree G1 + Go2）**
  - 模拟评估：20 个场景（12 名义 + 8 故障注入），使用硬件等价技能接口 + mock 适配器。
  - 物理验证：2 次真机试验，同一请求“bring me the red cube”，改变请求者位置以触发 HANDOVER（近端）或 CARRY（远端）工作流。
- **基准与指标**：工作流选择准确率、技能接地率、计划可执行率、契约违规率、虚假派发率、安全门召回率/精确率、规划延迟（秒）。

## 6. 主要结论与发现

- **接地是检索问题，安全是强制问题**：
  - 注入技能库使技能接地率从 51%（LLM-only）提升到 96%（Skill-list、RO-prompt、RO 三种条件相同），说明检索能修复“幻觉技能”。
  - 但只有知识而无强制时，信息充分的规划器仍会分派 23%（仿真）和 26–29%（人形–四足模拟）的故障步骤，故障场景的安全门召回率为 0%。
  - RO 强制将虚假派发降到 0%，安全门召回率/精确率均达 100%，并正确拒绝全部 8 个注入故障。
- **保持计划不变的消融**：相同计划经 RO-prompt 有 25.7% 虚假派发，经 RO 后降到 0%，证明因果来自运行时门控，而非计划质量改善。
- **结构化通道旁路（Structured-Channel Bypass）**：当感知坐标损坏（NaN）时，未强制的 LLM 会从周围文本中“脑补”一个貌似合理的坐标并照样派车；RO 通过状态接口绑定，检测到缺失/非有限值后硬拒绝，关闭了这一旁路。
- **检索诱导的替代（Retrieval-Induced Substitution）**：提供更多知识会使模型从明显幻觉（如不存在的技能）转向貌似合理的错误替代（如把无效目的地 `rooftop_helipad` 悄悄换成已注册的 `dropoff`），需要请求包含性检查来拦截。
- **实时执行证实差异的物理性**：没有强制时，8 个注入故障中 8 个都穿过编排边界，其中 6 个产生真实机器人运动；有强制时，8 个全部在运动前被拒。

## 7. 优点

- **架构清晰且原则性强**：将“推理”与“执行”分离为无重叠权限的组件，定义严格、职责分明。
- **实验设计精巧**：通过“检索 × 强制”双因子完全交叉设计（LLM-only / Skill-list / RO-prompt / RO）精确解锁知识增益与安全增益；“保持计划不变”消融排除了规划器随机性混杂，因果论证扎实。
- **动态绑定建模有洞察力**：识别出“某些关键事实在规划时不存在”这一被普遍忽略的漏洞，并用状态接口和运行时解析解决。
- **从仿真到真机的迁移验证**：同一套技能库/契约/编排器无需修改即可部署到物理人形和时间四足机器人，体现了框架的通用性。
- **指标区分度好**：分别报告“规划器行为”和“执行结果”，能清晰区分“提议错了”和“执行了错的提案”。
- **对失败模式的表征有启发性**：提出“检索诱导的替代”和“结构化通道旁路”两个概念，对未来安全 LLM-机器人系统有警示价值。

## 8. 不足与局限

- **真机试验规模非常小**：人形–四足只有 2 次硬件演示，未形成统计结论，物理场景仅覆盖“近端直接交付/远端装载运输”一种任务类型。
- **故障注入均为人造且规则可覆盖**：8 类故障属于预先定义好的违规类型，RO 可精确识别；未考察未预期故障、软硬件交互故障、感知噪声等复杂情况。
- **门控只保证“技能可执行”，不保证“技能执行成功”**：作者自己也承认，已授权技能内部的物理失败（如抓取失败、导航碰撞）需要下游恢复机制，本文未深入处理。
- **规划器能力有限**：规划器只在少量预先枚举的工作流契约中选择（原型简化），并未在高维组合空间中搜索；架构声称可与更强规划器兼容，但未验证。
- **可扩展性存疑**：手写技能库和工作流契约在技能库扩大后可能难以维护；作者仅将“契约层能扩展到多大”列为开放问题，未提出答案。
- **模型单一**：所有实验只用 `gpt-5.4-mini`，未比较不同基础模型下的替代错误率或门控行为，外部效度有限。
- **算力信息缺失**：未报告能耗、硬件数量或成本，不利于评估部署门槛。
