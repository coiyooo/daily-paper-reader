## 摘要
在分层视觉-语言-动作(VLA)系统的每个重新观测点，必须做出两个接口决策：何时终止当前子任务，以及执行所提出的动作分块的距离多远。这两个决策相互依赖——最优停止点取决于执行器计划做什么，而最优执行长度取决于子任务边界在哪里——然而现有架构将它们孤立地评估，这种不对称是任一模块都无法单独克服的。我们提出SparkVLA，一种停止感知的分层VLA，通过将两个决策表述为单一排序来解决这种相互依赖：停止与候选集中的每个动作前缀长度竞争，系统选择得分最高的选项，消除了阈值调整，仅需要离线序数偏好。锚定条件上下文编码模块缓存历史感知的子任务锚定编码、起始状态记忆和目标语义，引导视觉令牌剪枝朝向任务相关区域；停止感知动作前缀选择头在分块边界通过全自注意力对所有候选进行评分以提高效率。在RoboCerebra上，SparkVLA实现了47.12%的成功率，超过官方分层基线30.57%，超过最强可复现方法26.83%。在多步任务上的真实机器人实验进一步验证了这些增益在物理硬件上的表现。

## Abstract
At every re-observation point in a hierarchical Vision-Language-Action (VLA) system, two interface decisions must be made: when to terminate the current subtask and how far to execute the proposed action chunk. These decisions are mutually dependent---the optimal stopping point depends on what the executor plans to do, while the optimal execution length depends on where the subtask boundary lies---yet existing architectures evaluate them in isolation, an asymmetry neither module can overcome alone. We present SparkVLA, a stop-aware hierarchical VLA that resolves this mutual dependency by formulating both decisions as a single ranking: Stop competes against every action-prefix length in a unified candidate set, and the system selects the highest-scoring option, eliminating threshold tuning and requiring only offline ordinal preferences. An Anchor-Conditioned Context Encoding module caches a history-aware subtask anchor encoding onset-state memory and goal semantics, guiding visual-token pruning toward task-relevant regions; a Stop-Aware Action-Prefix Selection head scores all candidates via full self bnattention at chunk boundaries for efficiency. On RoboCerebra, SparkVLA achieves 47.12% success rate, surpassing the official hierarchical baseline by 30.57% and the strongest reproducible method by 26.83% Real-robot experiments on multi-step tasks further validate these gains on physical hardware.

# SparkVLA 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：分层视觉-语言-动作（Hierarchical VLA）架构通常由高层 VLM 规划器与低层 VLA 执行器组成，用于解决长时程多步操作任务。现有研究（如 HiVLA 的系统性研究）已指出，高低层接口机制——尤其是**终止条件**和**执行时域**——是最影响系统性能的设计选择。
- **核心问题**：在每个重新观测（re-observation）边界，系统必须同时决定：
  1. **何时终止当前子任务**（stop / termination）；
  2. **当前动作分块应执行多长**（action chunk execution length）。
- **关键洞察**：这两个决策是**相互依赖**的——最优的停止点取决于执行器接下来的计划内容，而最优的执行长度又取决于子任务边界在哪。然而现有方法将两者**孤立处理**：
  - 终止侧：使用二元停止检测器、VLM 预测长度或进度信号，无法访问即将执行的动作计划；
  - 分块侧：DEHP、ACH、AQC、AAC 等方法只能自适应选择执行长度，无法给出子任务完成信号。
- **本文主张**：这种"结构性的信息不对称"是现有架构无法单靠某个模块克服的。SparkVLA 将二者统一为**一个排序问题**，让"停止（Stop）"与"所有动作前缀长度"在同一候选集中竞争，从根本上解决相互依赖问题。

## 2. 方法论：核心思想、关键技术细节、算法流程

### 2.1 总体思想
- 将子任务终止与执行时域选择统一建模为：在一个候选集 \(\mathcal{C} = \{0, 1, \dots, H\}\) 上排序，其中 `0` 表示 Stop，`n≥1` 表示执行动作块的前 n 个动作。
- 模型选择得分最高的候选，实现**无阈值调参**、**仅需离线序数偏好**训练的联合决策。

### 2.2 整体架构
- 基于预训练 π0.5 VLA 派生两个分支：
  - **高层分支**：使用 π0.5 的 VLM backbone，既负责按自回归方式生成子任务指令 \(c_k\)，也承载动作前缀选择器；
  - **低层分支**：使用完整 π0.5（含动作专家）生成动作块 \(A_t = (a_t, \dots, a_{t+H-1})\)。

### 2.3 Anchor-Conditioned Context Encoding（锚点条件上下文编码）
- **历史感知子任务锚点（History-Aware Subtask Anchor）**：
  - 在子任务开始时，从规划器末层隐藏表示提取"原始锚点" \(\hat{\alpha}_k\)；
  - 维护锚点历史池 \(A_k=\{\hat{\alpha}_1,\dots,\hat{\alpha}_{k-1}\}\)，通过自注意力融合当前锚点与历史锚点，得到 \(\alpha_k\)，从而携带"哪些区域已被操作过"的记忆信息。
- **锚点引导的视觉令牌剪枝（Anchor-Guided Visual Pruning）**：
  - 冻结的 SigLIP 视觉编码器产生稠密视觉令牌；
  - 使用可微分的 Grid-Sampler 预测 K 个归一化 2D 坐标，条件于锚点 \(\alpha_k\)，通过双线性采样提取 K 个任务相关令牌，减少视觉序列长度。
- **高层隐藏特征编码**：
  - 剪枝后的视觉令牌投影到 backbone 宽度，与本体感觉状态、子任务指令嵌入拼接；
  - 通过高层 VLM 前 \(\ell_m\) 层（带 LoRA）获得用于排序的当前上下文特征 \(m_t\)。

### 2.4 Stop-Aware Action-Prefix Selection（停止感知动作前缀选择）
- 在决策边界，选择头接收动作块 \(A_t\)、缓存的锚点 \(\alpha_k\)、当前高层特征 \(m_t\)，输出 \(H+1\) 维分数 \(s_t\)。
- **统一候选打分**：
  - Stop 使用可学习嵌入 \(e_0\)；
  - 每个长度 n 候选由该前缀最后一个动作表示加上可学习的长度嵌入初始化，即 \(e_n = \text{MLP}_a(a_{t+n-1}) + p_n\)；
  - 将上下文 token \(e_\alpha, e_m\) 与所有候选 token 一起送入**全自注意力 Transformer**，使每个候选能够参考完整动作块及其他候选；
  - 打分层将每个候选输出映射为标量分数。
- **训练目标**：由成对排序损失 \(L_{\text{rank}}\) 与停止感知辅助损失 \(L_{\text{stop}}\) 构成。
  - 序数优先级的核心原则：
    - 子任务完成后，Stop 优先级最高；
    - 完成前，能覆盖到边界的动作前缀优于不覆盖的，且覆盖中越接近边界越好；
    - 失败轨迹中，所有动作前缀并列高于 Stop（鼓励继续探索）。
  - 训练时对边界标注施加随机扰动 \(\tau'=\tau+\Delta, \Delta\sim U(-2,2)\) 以增强鲁棒性。
- **推理**：直接用 \(\hat{n}_t = \arg\max_{i \in \mathcal{C}} s_{t,i}\)，并在提交 Stop 前使用一个短确认窗口过滤瞬时波动。

### 2.5 算法流程（文字描述）
1. 初始化语义历史 \(H_1=()\) 和锚点历史 \(A_1=()\)，获取观测与本体状态；
2. 子任务 k 开始时，高层规划器生成子任务指令 \(c_k\)，提取并缓存历史感知锚点 \(\alpha_k\)；
3. 在决策边界 t，低层执行器输出动作块 \(A_t\)，并重新计算锚点条件高层特征 \(m_t\)；
4. 选择头对 Stop 与所有前缀长度统一打分；若选择前缀 n，则执行前 n 个动作后重新观测，回到步骤 3；
5. 若选择 Stop，则将 \(c_k\) 追加到历史，更新锚点历史，进入下一子任务，直到满足全局终止条件。

## 3. 实验设计：数据集/场景、基准与对比方法

### 3.1 基准与数据集
- **RoboCerebra**（主基准）：大规模长时程操作基准，包含 1,000 条带标注轨迹、100 个任务变体，平均 9.1 个子任务、2,972 步。分为六个条件：
  - Dynamic（随机布局/变化观测）、Memory（子任务历史记忆）、Mix、Ideal 等；评估用 60 个预留用例 × 10 次 rollout，共 600 个 episode。
- **LIBERO**：包含 Spatial、Object、Goal、Long 四个套件，共 40 个任务，每任务 100 个 episode；子任务标注来自 LaRA-VLA。
- **真实机器人**：AirbotPlay 双臂平台（两个腕部相机 + 一个头部相机），三个多步任务：
  - Shelf Arrangement（6 个子任务）、Drawer Restocking（6 个子任务）、Tea Preparation（12 个子任务）；每任务 50 条演示、50 次 rollout。

### 3.2 对比方法
- **Standalone VLA**：OpenVLA-OFT、SmolVLA、π0.5。
- **Hierarchical VLA**：
  - HPE（RoboCerebra 官方分层基线）；
  - Mem-0（近期开源分层 VLA，作者在 RoboCerebra 上复现）；
  - 另有两个 SparkVLA 变体：低层执行器分别换成 OpenVLA-OFT 和 SmolVLA，以验证高层系统对不同执行器的泛化性。
- 实验统一采用官方评估协议、相同任务指令/观测流/动作接口/成功准则/重置分布，并控制训练数据与算力预算；所有方法在本地复现时采用匹配的微调协议。

### 3.3 主要结果
- **RoboCerebra**：SparkVLA 平均成功率 47.12%，比 HPE（16.55%）高 30.57 个百分点，比复现的 Mem-0（20.29%）高 26.83 个百分点，比 standalone π0.5（12.29%）高 34.83 个百分点。
- **增益最大的场景**：Dynamic Obs（+34.78 pp）和 Memory Exp（+47.69 pp）。
- **LIBERO**：SparkVLA 平均成功率 98.5%，其中 LIBERO-Long 达 98.0%，明显高于 π0.5（92.4%）等基线。
- **真实机器人**：SparkVLA 平均成功率 69.3%，比 π0.5（48.0%）高 21.3 个百分点；在 12 子任务的 Tea Preparation 上优势最大（+30.0 个百分点）。
