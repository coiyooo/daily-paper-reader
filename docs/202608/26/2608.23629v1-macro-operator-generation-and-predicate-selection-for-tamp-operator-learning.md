## 摘要
手工创建符号算子是部署任务与运动规划系统（TAMP）的主要瓶颈之一。近期研究表明，这些算子可以直接从演示数据中学习得到。然而，现有方法通常孤立地学习每个动作，无法捕捉操作任务中反复出现的多步结构，导致搜索在长序列任务上变得难以处理。另一个效率问题出现在符号状态中：每个提供的谓词都会在每个搜索节点被评估，即使它从未出现在任何学习到的算子中。我们提出了一种同时解决这两个问题的系统。其核心组件是宏算子的自动生成——将重复出现的单个动作序列压缩为单一规划步骤的复合动作。我们的系统直接从训练数据中发现因果关联的动作对，其中前一个动作恰好产生后一个动作所需的条件，并将每一对动作转换为新的算子。此外，我们的系统会剪枝所有未被任何学习算子引用的谓词，从而缩小每个搜索节点评估的符号状态。这些改动共同缩短了有效规划范围，其带来的收益随任务长度的增加而增大。在四个TAMP领域上，与基线方法（即Learning Operators for TAMP）相比，我们的方法实现了最高4.6倍的规划加速。更重要的是，它能解决基线方法无法解决的长序列任务。因此，宏算子发现不仅加速了规划，而且在某些领域中决定了实际的可求解性。

## Abstract
Creating symbolic operators by hand is one of the main bottlenecks in deploying Task and Motion Planning systems (TAMP). Recent works show that these operators can instead be learned directly from demonstration data. Existing methods, however, typically learn each action in isolation and cannot capture the recurring multi-step structure of manipulation tasks, so the search becomes intractable on long sequential tasks. A further inefficiency arises in the symbolic state: every provided predicate is evaluated at every search node, even when it never appears in any learned operator. We present a system that addresses both problems together. Its central component is the automatic generation of macro-operators, composite actions that compress a recurring sequence of individual actions into a single planning step. Our system discovers causally linked action pairs directly from the training data, where one action produces exactly the condition that the next one requires, and turns each pair into a new operator. Alongside this, our system prunes every predicate that no learned operator references, which shrinks the symbolic state evaluated at each search node. Together, these changes shorten the effective planning horizon, and the benefit they bring grows with the length of the task. Across four TAMP domains, our method reaches up to a 4.6x planning speedup compared to the baseline method, namely Learning Operators for TAMP. More importantly, it solves a long sequential task that the baseline cannot solve. Macro-operator discovery thus not only accelerates planning but, in certain domains, determines solvability in practice.

## 1. 论文的核心问题与整体含义（研究动机和背景）

任务与运动规划（TAMP）系统依赖手工编写的符号操作符（PDDL 风格的预条件和效果），这要求专家具备大量领域知识，是部署的主要瓶颈。已有工作（如 LOFT）可从演示数据中直接学习操作符，但存在两个突出缺陷：

- **孤立学习动作**：每个动作被独立学习，无法利用操作中反复出现的多步结构（如先拿起再放置）。在长序列任务中，规划器必须在每个搜索节点重新发现这些固定模式，导致有效规划范围被拉长、分支因子爆炸。
- **未被引用的谓词浪费**：用户提供的所有谓词在每个搜索节点都会被评估，即使它们从未出现在任何学习到的操作符中，增加了状态解析和符号搜索空间。

论文同时解决这两大问题：自动生成宏算子以压缩多步子程序，并通过迭代谓词选择（IPS）剪枝无引用谓词，从而缩短规划范围并减小搜索状态。该工作不仅带来加速，更在长序任务中决定了“能否找到计划”这一根本问题。

## 2. 论文提出的方法论

论文提出完整流水线，核心组件包括：

- **宏算子自动生成（Effect-Complement Analysis）**：直接从训练轨迹中寻找因果关联的动作对（前一个动作添加的谓词，恰好被后一个动作删除），并把每个可验证的动作对合并成一个复合操作符。算法分为四个阶段：
  - **Phase 1 一致效应识别**：基于 oracle 演示数据，为每个动作类型统计各谓词的添加/删除频率，以超过 50% 为阈值提取一致效应（Adds[·] 与 Dels[·]）。
  - **Phase 2 因果对挖掘**：对任意有序动作类型对 (ai, aj)，计算 L = Adds[ai] ∩ Dels[aj]；只保留包含至少一个对象参数谓词的候选对，避免零元全局谓词造成的虚假关联。
  - **Phase 3 验证与冲突消解**：在演示+随机探索数据中统计每个候选对连续出现的频率 f，保留 f > 0 的对；若同时存在互逆对 (a_i,a_j) 和 (a_j,a_i)，则只保留频率更高的一方。
  - **Phase 4 构建宏算子**：对保留的动作对做参数统一（例如 Pick(b1)+Stack(b1,b2) 合并为宏参数 (b1,b2)），并记录索引向量以便执行时还原。同时生成宏转换样本（从 xi 跳到 xi+2，跳过中间状态）。
- **宏算子学习集成**：
  - 为宏算子合成负例（从一个随机状态中尝试执行宏但状态不变）。
  - 将宏作为普通动作类型交给 LOFT 的算子学习模块，学习其预条件和效果。
  - 为宏算子设计顺序连续采样器（Sequential Sampler），按照子动作顺序采样连续参数（如 grasp pose 和放置位置），并复用共享参数，保证可行性。
- **迭代谓词选择（IPS）**：在算子学习完成后，仅保留至少在某个操作符的预条件或效果中出现过的谓词，其它谓词从状态表示中移除。该过程只需一次遍历 O，成本可忽略。

整体架构明确：训练数据 → 宏生成 → 算子学习（增强数据）→ IPS → TAMP 规划（A* + 连续采样） → 可执行计划。

- 在 Blocks 域，效果互补分析自动发现 Pick→PutOnTable（34.1%）和 Pick→Stack（28.0%）两个合理的宏，与人工直觉一致；学习到的宏算子（如 MacroPickStack）逻辑上等价于手写“拿起 b1 并叠到 b2”的规则。

- IPS 在 Cover 和 Blocks 分别将谓词数从 5→3 和 6→5，减少约 40% 和 17%，但对规划时间影响较小（如 Blocks 0.041→0.042s）。

## 7. 优点

- **方法新颖且实用**：将宏算子的自动发现直接集成到概率操作符学习框架中，利用数据驱动方式压缩多步结构，减少手工工程。
- **算法设计简洁有效**：效果互补分析可解释性强（在 Blocks 域发现结果与人类直觉一致）；参数统一和索引向量设计使宏能无损还原为原动作；顺序采样器解决了连续参数依赖问题。
- **架构兼容性**：宏被当作普通动作类型学习，不需要修改现有操作符学习模块，便于推广到其他基于 LOFT 的系统。
- **实验设计有层次**：从简单到长序任务逐步递进，并通过消融、无超时验证等方式增强了结论的可靠性。
- **成本极低**：宏生成和 IPS 都只增加一次性少量开销（训练时间最多增加 0.5s 以内），收益持续时间长。

## 8. 不足与局限

- **宏发现粒度有限**：只考虑两个连续动作对，不能捕获更长或嵌套的序列（如 pick-wash-dry-place），对更深层的关键子程序无法抽象。
- **谓词无法自动创造**：IPS 只能剪枝无用谓词，无法从感知数据中发现新的谓词，领域工程负担仍存在。
- **连续采样器仍为手动设计**：为宏设计的顺序采样器和底层采样器都需要人工提供，论文未实现学习采样器。
- **仅在仿真中验证**：所有实验均在 PyBullet 中运行，未处理真实世界的感知噪声、执行误差和 sim-to-real 迁移。
- **批处理离线模式**：算子一次性从固定数据中学习，无法在线增量更新，难以适应长期部署中任务分布变化的情况。
- **实验统计力度有限**：种子数、问题数偏少，且缺少与其他宏学习方法及更长基准的对比，结论的普适性和显著性需要更多验证。
- **短任务性能退化**：在 Cover 域中宏算子导致轻微的成功率下降和明显时间增加，表明缺乏自适应地决定是否使用宏的机制。
- **对负例合成的依赖**：宏负例通过人为构造“状态不变”的转换获得，可能引入噪声，影响所学预条件的准确性，论文未对此做鲁棒性分析。
